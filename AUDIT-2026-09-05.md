## 1. Every nebula control is inert when auto-rotate is off

**Where:** `src/render/Nebula.ts:225` (`prepareFrame`), `:233` (`render`)
**Severity:** high — a persisted user setting disables four visible controls

`prepareFrame` skips the raymarch when the camera has not moved:

```ts
this.skipRender = !moving && pose === this.lastPose;
```

But `uDensity`, `uIntensity`, `uLayout` and `uBound` all live on
`marchMaterial`, and the composite pass does nothing but blit
`this.target.texture`. So while the march is skipped, none of them can reach the
screen.

Measured with the camera at rest (headless Chromium, quality tier pinned to 3):

```
autoRotate=false : march skipped 181/181 frames over 3s
  then showNebula=false -> uDensity 0.956 -> 0.000
  and the march is still skipped 91/91 frames over the next 1.5s

autoRotate=true  : march skipped 0/181 frames
```

What breaks, with auto-rotate off and the camera untouched for >0.35s:

- the **Nebula intensity** slider
- the **Nebula** checkbox in Display
- the filter-driven density change in `App.applyNebulaDensity()` — the exact
  thing that method exists for ("narrowing 117k cards down to 13k changed almost
  nothing on screen")

Layout switches *do* still work, but only by luck: `moving` is also true while
`starfield.isMorphing`.

**Why nobody saw it:** `autoRotate` defaults to `true`, so the camera never
stops. But it is a checkbox in Settings *and* it is persisted by `persist.ts`,
so once a user turns it off it stays off across sessions.

**Fix:** invalidate the cached frame whenever a march uniform changes — set
`this.lastPose = ''` at the end of `setDensity`, `setIntensity`, `setLayout`
and `setWorldScale`, or add an explicit `invalidate()` those call.

**Repro:** load the app, `store.patchVisual({autoRotate:false})`, wait ~4s, then
`store.patchVisual({showNebula:false})` and watch `app.nebula.skipRender` stay
`true` while `app.nebula.marchMaterial.uniforms.uDensity.value` goes to 0.

## 2. Era markers point at the wrong rings

**Where:** `src/render/EraMarkers.ts:39`
**Severity:** medium — the feature's whole purpose is to be a landmark

The markers place labels by **linear year fraction**:

```ts
const t = (era.year - yearMin) / Math.max(1, yearMax - yearMin);
const r = GALAXY_CORE + (GALAXY_RADIUS - GALAXY_CORE) * Math.sqrt(t);
```

`layouts.ts::galaxy` places stars by **`chronoRank`** — `r / (n - 1)`, a
percentile over all 117,621 printings:

```ts
const t = chronoRank[i];
let r = CORE + (GALAXY_RADIUS - CORE) * Math.sqrt(t);
```

Those diverge badly, because Magic's print rate is nothing like flat. Measured
against `public/data/universe.bin` (n=117,621, yearMin 1993, yearMax 2026):

| era | marker r | true r | error | as % of disc |
|---|---|---|---|---|
| Alpha (1993) | 30.0 | 30.0 | 0.0 | 0.0% |
| Revised (1994) | 80.5 | 63.8 | +16.7 | 5.2% |
| **Modern (2003)** | **189.6** | **129.1** | **+60.5** | **18.9%** |
| 2026 | 320.0 | 311.8 | +8.2 | 2.5% |

"Modern" sits nearly a fifth of the disc radius outside the ring where 2003's
cards actually are.

**Fix:** take the era's radius from the same `chronoRank` the layout uses — the
`chronoRank` of the first card in that year — rather than from the year itself.

**Two smaller things in the same file:**

- The constructor scans all 117,621 rows for `yearMax` that
  `starfield.ctx.yearMax` already holds, then mixes in
  `new Date().getUTCFullYear()`. Once the runtime year passes the catalogue's
  build year, the markers drift against the stars they are labelling.
- Sprite aspect is `70 * (64/320)` = 0.2 in the constructor and `s * 0.22` in
  `update()`. The labels render ~10% taller than the texture they came from.

## 3. `?cards=` does not survive the first click

**Where:** `src/core/urlState.ts:75-83`
**Severity:** high — this is the headline feature of the release

The URL writer rebuilds the query from scratch and re-emits only `shell`,
`layout`, `card` and `set`. `cards` is never written back, so the first state
change that triggers a write drops it.

Reproduced end to end against the dev server:

```
arrival        ?shell=play&cards=Sol%20Ring%2CLightning%20Bolt%2CCounterspell
               -> 3 highlighted, 3 filtered, 304 matches
after a click  ?shell=play&card=003265d9-b2fc-4916-afc8-53ed2d6aa053
               -> cards= gone
after reload   (that URL)
               -> 0 highlighted, 0 filtered, 111,720 matches
```

The deck is gone on reload, and any link copied after a single interaction is
missing its whole point.

Impact is limited on the desktop surface: FND's retry button remounts the iframe
from `aetherQuery`, which the iframe's own `replaceState` cannot touch. It bites
the public site, browser reload, and any shared link.

**Fix:** re-emit `cards` in the writer from `store.state.filter.oracles` (or
keep the original token list around and write that back verbatim).

**Related round-trip failure in the same function:** `layout=galaxy` is
deliberately omitted from the URL, but the reader forces `layout='sets'`
whenever `set=` is present without an explicit layout. So filtering to one set
while in the galaxy layout produces `?set=X`, and reloading that jumps to the
sets layout.

## 4. `additionalBrowserArgs` silently drops wry's defaults

**Where:** `src-tauri/tauri.conf.json:40` (FND)
**Severity:** high on Windows — privacy and stability regression, shipped

```json
"additionalBrowserArgs": "--ignore-gpu-blocklist --enable-gpu-rasterization --enable-zero-copy --disable-gpu-driver-bug-workarounds"
```

Verified in the exact pinned crate, `wry-0.55.1/src/webview2/mod.rs:294`:

```rust
let additional_browser_args = pl_attrs.additional_browser_args.unwrap_or_else(|| {
  // remove "mini menu" - See https://github.com/tauri-apps/wry/issues/535
  // and "smart screen" - See https://github.com/tauri-apps/tauri/issues/1345
  let default_args = "--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection";
```

`unwrap_or_else` — supplying any value **replaces the entire default string**.
wry's own doc on `with_additional_browser_args` says so outright: *"so if you
use this method, you have to add these arguments yourself if you want to keep
the same behavior."*

Three separate problems:

1. **v3.7.0 on Windows re-enables `msSmartScreenProtection`** — a per-navigation
   Microsoft reputation check — in an app whose pitch is local tracking and no
   account. It also brings back the WebView2 mini-menu (wry#535) and the PDF
   out-of-process UI.
2. **None of the four flags asks for a discrete GPU.** That is
   `--force_high_performance_gpu`. The commit message says "ask WebView2 for a
   discrete GPU"; the change does not do that.
3. `--ignore-gpu-blocklist` and `--disable-gpu-driver-bug-workarounds` re-enable
   exactly the driver paths Chromium blocklists *because they crash* — on the
   most GPU-heavy page in the app.

**Suggested replacement:**

```json
"additionalBrowserArgs": "--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --force_high_performance_gpu"
```

Secondary note: wry warns that webviews with different browser arguments need
different data directories. Only one webview exists per process and
`tauri-plugin-single-instance` is in use, so this is probably fine, but it is
worth knowing if WebView2 environment creation ever starts failing after an
upgrade.

## 5. The sitemap entry was reverted one commit after it was added

**Where:** `website/sitemap.xml` (FND)
**Severity:** low, but currently live

`41f0d913` ("sitemap link the new path") hand-added:

```xml
<url><loc>https://filthy-net-deck.com/aetherfield/</loc>…</url>
```

`sitemap.xml` is a **generated** file — `pipeline/build-meta-site.mjs:1684`
writes it wholesale. The very next commit to touch it, `4d4ed652`, regenerated
it and dropped the entry. The current working tree has no aetherfield `<loc>`
and `lastmod` is back to 2026-09-04.

**Fix:** add the entry in `pipeline/build-meta-site.mjs`, not in the output.

## 6. "Save this view" is dead on macOS

**Where:** `src/ui/bookmarks.ts:50`
**Severity:** medium — a feature that silently does nothing on one platform

```ts
const name = window.prompt('Name this view', store.state.layout);
if (!name) return;
```

wry 0.55.1 ships no `WKUIDelegate` text-input panel — there is nothing in
`wry-0.55.1/src/wkwebview/` that handles a script dialog. Under WKWebView, an
unimplemented `runJavaScriptTextInputPanel` means `prompt()` resolves to `null`.
So on macOS the button does nothing, with no error and no feedback. FND ships a
universal `.dmg`.

Windows (WebView2) and Linux (WebKitGTK) both provide default dialogs, which is
why this was not caught locally.

**Fix:** an inline text field in the bookmarks panel. It also removes the
"modal dialogs block the webview" hazard entirely.

**Also in `bookmarks.ts`:** `loadBookmarks()` (line 78) validates only `id` and
`name`. `applyBookmark` then feeds an unvalidated `layout` string straight into
`store.set('layout', …)` and spreads a possibly-`undefined` `camera` into a
cue — giving `rig.restore()` a NaN pose. `persist.ts` next door is scrupulous
about exactly this and explains why in its header ("Storage is shared with
whatever else lives on this origin — inside a host app, that is the host"). Same
storage, same risk, opposite treatment. `crypto.randomUUID()` also needs a
secure context.

## Smaller findings

### `--mcu-inset-left` is scaled twice

`filters.ts:432` writes the inset in **screen** px (already multiplied by
`uiScale()`) onto `#ui-root` — which is the exact element `scale.ts:70` puts
`zoom` on. Every px length inside that subtree gets multiplied by the zoom
again.

Measured at 1100×640 (zoom 0.85, filter panel open):

```
panel right edge on screen : 255.0
store.insets.left          : 270    (correct)
--mcu-inset-left           : 270px  (consumed inside zoom:0.85 -> 229.5 effective)
layout switcher centre     : 664.8
centre of the free area    : 677.5
                             -12.8px off
```

The camera framing is **correct** — `App.viewport()` reads the store in JS,
outside the zoom. Only the CSS chrome (`.mcu-layout-switcher`,
`.mcu-bookmarks-wrap`) drifts. Fix: divide by `uiScale()` when writing the
variable, or set it on `document.documentElement` instead of the zoomed root.

### `Aetherfield.tsx` effect dependencies

`src/pages/Aetherfield.tsx:145` — deps are `[attempt, trackerMatches]`.

- Every tracker update tears down the `message` listener and **restarts the 45s
  boot timer**. During a game that can be often enough that a genuinely dead
  frame never reaches the fallback.
- `pushCollection` is only called on the `ready` message, so a tracker change
  after boot never reaches the galaxy — despite `trackerMatches` being a
  declared dependency. The dep array implies an intent the body does not honour.
- The effect does not depend on `src`, but the iframe `key` does. A src-driven
  remount would leave `status` at `"ready"` with no new timeout armed. Latent
  today (the page unmounts on navigation, so `src` cannot change while mounted),
  but it is one routing change away from being live.

**Fix:** hold `trackerMatches` in a ref, depend on `[attempt, src]`, and reset
`status` to `"booting"` when `src` changes.

### `urlState.ts:60` double-decodes

```ts
else for (const o of universe.oraclesNamed(decodeURIComponent(t))) oracles.add(o);
```

`URLSearchParams.get()` already decoded. Harmless for real card names, but
`decodeURIComponent` **throws** on a malformed `%` sequence, and that throw
propagates out of `connectUrlState` into `main()`'s catch — one bad token in a
deep link becomes a full boot-error screen instead of a skipped card. Drop the
call.

### `embed.ts:117` does not check `event.origin`

`onHostMessage` checks the channel tag but not the origin. The host side
(`Aetherfield.tsx:116`) does check `event.source`. Payloads are benign
(highlight / show-set), so this is hygiene rather than a hole, but the asymmetry
is worth closing.

### `bakeClusterMap` is uncached

`Nebula.ts` — 128² × 1049 sets with an `exp()` per pair, on the main thread,
**every** time the sets layout is entered, not just the first. Measured:

```
switch galaxy -> sets : 56.1, 48.2, 48.3, 49.0 ms
```

~3 dropped frames per switch. Cache the baked texture by layout.

### Leaks and nits

- `Nebula.setLayout` disposes the previous cluster texture only
  `if (prev.image.width > 1)`, so the 1×1 dummy never gets freed — and
  `dispose()` then frees the baked one instead of it.
- `Nebula.frozenTime` is written in `render()` and never read anywhere.
- `Universe.oraclesNamed` calls `buildNameIndex()` **inside** its scan loop.
  Cost is genuinely fine (measured 10.3 ms for 100 names over 39,849 unique
  names), it is just in the wrong place.
- `App.updateStats` shadows the global `window` with `const window = this.fpsAccum`.
- `CardBillboards.hitTest` runs 48 `raycaster.intersectObject` calls per frame
  whenever the pointer is over the canvas; each allocates.
- `App.frame()` builds a 7-`toFixed` template-literal pose string per frame
  while the pointer is inside.

### i18n: non-reactive `t` at the two new call sites

`DeckView.tsx:516` and `Sets.tsx:406` call the **module-level** `t` (which reads
a module-scoped `current` locale) inside components that never call
`useLocale()`. They update on a language switch today only because an ancestor
does subscribe and re-renders them — `App` (via `useLocale` at `App.tsx:135`)
for DeckView, and `Sets()` (line 972) for `SetGallery`. Correct now, but it
breaks the moment either child is wrapped in `memo`. Every other call site in
those files uses the hook.

## One design question

`?cards=` **filters** the galaxy down; the host's `highlight` message only
highlights. Measured: a three-card deep link leaves 304 of 117,621 printings
visible. For a 100-card Commander list that is a few thousand scattered stars on
an otherwise empty field — the galaxy reading is lost entirely.

The highlight-in-context behaviour (what `pushCollection` already does) is
probably what the "Show deck in galaxy" button wants. Worth deciding
deliberately, since the two entry points currently disagree.

## Test coverage gap

The common thread behind findings 1, 3 and 6: `npm run test:interaction`
exercises `?layout=` and `?card=` but nothing for `?cards=`, `?set=`,
`?shell=`, the embed message channel, bookmarks, or the settings controls.
Those are precisely the surfaces where the bugs above live.

## Suggested order

Three of these are affecting people running v3.7.0 right now:

1. **#4** — `additionalBrowserArgs`. One-line config change, ships privacy and
   stability back to where they were.
2. **#3** — `?cards=` round-trip. The release's headline feature does not
   survive a reload.
3. **#1** — nebula freeze. One persisted checkbox away from four dead controls.

Then #2 (era markers), #6 (macOS prompt), #5 (sitemap generator), and the
smaller items as convenient.
